# Purposeful Use

Start from the learning goal, then ask whether AI adds value to it at all. If it does, choose the tool and epistemic architecture (the arrangement of models, agents, and methods) that fits the thinking task. One model, a dedicated tool, delegated perspectives, a multi-model panel, and no AI at all are different tools. Use more only when it gives the learner something they need.

**Why:** AI is one part of a learner's digital literacy, not the default answer to every task. Starting from the tool rather than the goal leads to AI that is merely present, not useful. Unnecessary use wastes time, money, and attention. It also consumes real resources, water and electricity, especially in long-running and parallel work. Over-orchestration can do the learning *for* the learner, for example a swarm producing a polished synthesis of a topic the learner needed to read their way into. And if every request triggers a panel, no one can tell which part of EXplore actually improved the learner's thinking.

**Pattern:**
- **Goal before tool.** Establish what the learner is trying to learn, decide, or produce. Then decide which steps, if any, need AI.
- **Is AI the best choice?** Before using it, consider whether a non-AI tool or the learner's own effort serves the goal better. Examples: reading a primary source, a library database, talking to a person, working a framework by hand, or reflecting. When the learning is in the doing, say so and support it rather than substituting for it.
- **General model or dedicated tool.** A general model suits brainstorming, explaining, and checking work against criteria. Literature search, data analysis, and citation lookup are better served by dedicated tools and databases. Use the scholarly search tools where available rather than a model's recall.
- **Scale deliberately:**

  | Task | Arrangement |
  | --- | --- |
  | Simple explanation | One model |
  | Source check | One specialist with tools |
  | Exploring consequences | Two or three delegated perspectives |
  | Contested argument | Questioning from several independent lenses |
  | Model comparison or triangulation | Multi-model panel |
  | Reflection | One Socratic agent; the learner writes |

- **Compare when the choice matters.** When tool choice affects the result, trying the same task in two tools is itself a useful learning exercise. Use it deliberately, not by default.
- **Load only what's needed.** Don't run every workflow or apply every thinking framework to a simple request.
- **Bound the run.** Cap searches, agents, and rounds. Stop unproductive trails and report what remains. Always offer a single-agent option.
- **Be honest about environmental cost.** Acknowledge that larger, longer, and parallel runs use more resources. Don't present token counts as measured environmental impact, and don't invent figures.

**Boundaries:**
- This is not about minimising AI for its own sake. When independent perspectives, parallel search, or a model comparison genuinely serve the inquiry, use them.
- Proportion applies to process too. Don't ask setup questions the workspace already answers.
